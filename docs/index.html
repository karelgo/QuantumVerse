The moment we're in

Every field gets one moment like this.

2008

Code outgrew tarballs.

Patches on mailing lists, releases on FTP. GitHub gave code a home, a social layer, and a unit of collaboration — the pull request.

2019

Models outgrew FTP servers.

Weights scattered across university servers. Hugging Face gave models a standard artifact and a one-line way to reuse a stranger's work.

Now

Quantum has no home.

Thousands of circuits, trained ansätze, and hardware results every week — shared as PDFs and framework-locked zip files that stop reproducing when the hardware drifts.

The gap

The layer nobody owns.

Frameworks are silos.

Qiskit, Cirq, PennyLane, Braket, CUDA-Q — a circuit written in one is dead weight in another, even though OpenQASM 3 and QIR exist precisely to bridge them.

Hardware is a moving target.

Devices are recalibrated daily. A result produced on Tuesday can be unreproducible on Thursday — on the same machine. No other field of computing has this problem.

Reusable work isn't reused.

A converged VQE ansatz, a hardware-tuned transpilation, a mitigation recipe — real money in QPU time, evaporating the day the paper ships. There is no from_pretrained for quantum.

Claims can't be checked.

"Quantum advantage" arrives as a press release. There is no live scoreboard where a claim comes attached to the raw shots, the device snapshot, and a replay button.

Cloud aggregators sell access. Benchmark platforms verify benchmarks. Catalogs list circuits. Dataset projects host curated data. Each owns one column — nobody owns the artifact layer that ties them together: shareable, framework-agnostic, verifiable quantum objects. That layer is where GitHub-scale network effects live.

The platform

Three pillars.

Pillar I · The Hub

One line to use anyone's work.

Typed, versioned artifact repositories — stored framework-agnostically over OpenQASM 3 and QIR, exported to whatever framework you use. Every circuit ships with a Circuit Card: qubits, depth, T-count, noise sensitivity, and verified per-backend results.

Trained VQE and QAOA parameters are the pretrained weights of quantum — expensive to produce, free to reuse, hosted nowhere today. When reusing a stranger's converged ansatz is one line and reproducing it is a week of QPU budget, every consumer becomes a publisher.

Pillar II · The Verification Layer

The pillar GitHub and Hugging Face never needed.

In classical computing, code is the result. In quantum, a result is code plus a device plus that device's state at a specific hour — and most published results can't be independently reproduced. QuantumVerse makes verifiability a platform primitive.

  • Experiment Capsules — a git commit for a quantum experiment: content-addressed, citable, forkable, replayable on today's calibration.
  • Semantic circuit diffs — GitHub diffs text; QuantumVerse diffs unitaries, via ZX-calculus equivalence checking.
  • Quantum CI — equivalence checks, resource-count regression, simulator validation, optional metered runs on real QPUs.
  • Verified leaderboards — Papers-with-Code for quantum, machine-verified. The endgame: every advantage claim gets asked "where's the capsule?"

Pillar III · The Playground

Nobody shares a platform. Everybody shares a demo.

Every circuit page has a Run button — a WebAssembly statevector simulator executes up to ~25 qubits in the browser, no signup, no install. You already used it: the circuit at the top of this page is real.

  • Embeds everywhere — live, runnable circuit widgets for blogs, docs, arXiv HTML, and course pages. Every embed is an inbound door.
  • Circuit Golf — competitive circuit optimization with the equivalence checker as referee. Fewest gates wins. The community's game.
  • The Readiness Meter — every algorithm answers the question every visitor silently asks: when does this become real?

Why this catches on

Platforms don't win on features. They win on compounding loops.

Hub

The reuse loop

Loading trained parameters saves real QPU money → consumers publish so others reciprocate → more artifacts, more reasons to come.

Verification

The credibility loop

Capsules make results citable and checkable → researchers link them in papers → readers arrive → their next experiment ships as a Capsule.

Playground

The education loop

In-browser running makes it the easiest place to learn quantum → courses embed it → every student is a future publisher.

Community

The status loop

Verified badges, leaderboard ranks, and golf trophies are portable reputation — in a young field where reputation is scarce and precious.

And one structural advantage: the field is small enough to win. GitHub needed millions of users to tip. The active quantum community is tens of thousands of people who read the same arXiv listings and attend the same five conferences. Indispensable to five thousand of them is victory — before the growth curve goes vertical.

Beyond the horizon

What the artifact layer makes possible.

Frontier 01 · The Drift Observatory

A weather map for quantum hardware.

Every Experiment Capsule already carries a device calibration snapshot. Aggregate them over time and you get the thing no one keeps today: the longitudinal record of how quantum hardware actually behaves — which machines are healthy, which just degraded, which recovered after a recalibration. It's the control group reproducibility needs, and a public dataset in its own right.

ibm_kingston · 30-day drift simulated preview
Frontier 02

Agent-native by design

An MCP server exposing search, load, verify, and publish — so AI assistants are first-class users, pulling checked baselines instead of hallucinating circuits. Agents compete in Circuit Golf too, with the equivalence checker as referee.

compounds the reuse & education loops
Frontier 03

Federation

Self-hosted instances — a lab, a company, a national facility — that keep sensitive work private and sync public capsules to the commons like git remotes. Possible only because the formats are open specs. Neutrality becomes architecture, not a promise.

compounds all four loops, structurally
Frontier 04

The Quantum CV

A profile that is earned, not claimed: capsules authored, provider-verified results, golf rank, review contributions. The first verifiable quantum résumé — cryptographic backing instead of vibes, in a field where hiring is guesswork.

compounds the status loop
Frontier 05

Capsule-backed publishing

A "reproducible" badge and an overlay-journal path: reviewers replay a capsule in one click instead of squinting at figures. Editors get a policy dial — "hardware results require a provider-verified capsule." Infrastructure for the scholarly record.

compounds the credibility loop, into academia

None of these are features bolted on. Each falls out of a decision the vision already made — capture the device snapshot, publish the format as a spec, verify instead of trust — and pays it forward into a new domain. Read the full sketch in FRONTIERS.md.

The hardware layer

A profile page for every machine.

Hardware as publisher, not just backend

The industry's fastest-growing fleet is invisible.

Full-stack vendors like IonQ sell access to machines the whole world can see. But merchant foundries like QuantWare have shipped QPUs to 50+ customers in 20 countries — labs building their own quantum computers. Those machines are on no cloud, no aggregator list, no leaderboard: real hardware with no public identity, no benchmark record, no calibration history. QuantumVerse gives every physical QPU a home — a Device Card that is to a machine what a Circuit Card is to a circuit.

Hardware 01

The Device Registry

A vendor-neutral registry of physical QPUs — cloud-hosted or homebuilt. Identity, topology, native gates, chip lineage, per-machine calibration timeline, and every verified capsule ever minted on it. Machines become citable: "runs were performed on qv:device/…".

compounds the credibility & status loops
Hardware 02

Self-hosted QPU runners

The GitHub Actions runner model, applied to hardware: labs register their machines to accept benchmark and CI jobs in idle time, returning signed capsules. Owners get continuous public proof their machine works; the platform gets a real fleet without owning a fridge.

compounds the reuse & credibility loops
Hardware 03

The birth certificate

A standardized, capsule-backed commissioning suite every new machine runs on day one — the vendor-neutral nutrition label QPU procurement is missing. Buyers write it into contracts; foundries ship it with every processor: verified on QuantumVerse.

compounds the credibility loop, upstream into procurement
Hardware 04

Fleet telemetry

The Drift Observatory's B2B face: opt-in, owner-controlled, aggregated field data on how a vendor's chips behave across the installed base. Labs get fleet-relative context; chip makers get the fab-to-field feedback loop no one can build alone.

compounds the reuse loop, at the silicon level

Neither archetype is asked to change its business. The cloud vendor keeps selling access — and gains the neutral credibility no self-published metric can buy. The foundry keeps selling processors — and its customers' machines finally become visible, provable, and comparable. The platform sells neither; it makes both legible. Full design in HARDWARE.md.
